2 ЗАВДАННЯ

     На цій лабораторній роботі потрібно розробити front-end частину програмної системи. Ця частина системи повинна підтримувати роботу клієнтів у веб-режимі та забезпечувати адміністрування системи, тобто мати окремий інтерфейс для звичайних користувачів і окремий — для адміністраторів (відповідно до ролей користувачів вашої системи). Користувацький інтерфейс та інтерфейс адміністрування повинні підтримувати інтернаціоналізацію та локалізацію, а саме, забезпечувати: підтримку української на англійської мов сайту, формат дати та часу відповідний регіону, порядок сортування текстових значень, різні напрями введення тексту тощо. Адміністрування системи повинно забезпечувати: управління користувачами системи, управління даними системи, створення резервних копій налаштувань та даних, експорт та імпорт даних та налаштувань.

     3 ОПИС ВИКОНАНОЇ РОБОТИ

     Система являє собою єдиний цифровий простір для управління притулками для тварин. У ході виконання лабораторної роботи було спроєктовано архітектуру веб-клієнта, розробленого мовою JavaScript з використанням бібліотеки React.js.
     Опис прийнятих інженерних рішень:
* архітектурний підхід (SPA & Component-based): Застосунок побудовано як Single Page Application. Інтерфейс розділено на незалежні компоненти, що забезпечує перевикористання коду та швидкий рендеринг без перезавантаження сторінки;
* маршрутизація та безпека (Protected Routes): Для навігації використано react-router-dom. Написано компонент ProtectedRoute, який перевіряє JWT-токен та роль користувача (AuthContext) перед наданням доступу до адміністративних панелей;
* мережева взаємодія: Для зв'язку з бекендом (Node.js/Express) використовується бібліотека axios. Дані передаються у форматі JSON через REST API;
* інтернаціоналізація та локалізація (i18n/l10n): Застосовано бібліотеку i18next. Реалізовано динамічну зміну мови (українська/англійська), форматування дат відповідно до локалі (Intl.DateTimeFormat), локалізоване сортування масивів (localeCompare) та динамічну зміну напрямку тексту (LTR/RTL) на рівні DOM-дерева;
* робота з бінарними даними (Export/Import): Для функції Адміністратора системи реалізовано алгоритм завантаження резервної копії БД у форматі JSON та безпечний імпорт через транзакції knex на бекенді з відновленням консистентності зовнішніх ключів (Foreign Keys) та автоінкрементів (Sequences).
     Для наочного представлення структури, поведінки та архітектури розробленого веб-клієнта було побудовано ряд графічних моделей (візуалізація наведена у Додатку Б):
* UML діаграма прецедентів (Use Case Diagram): Відображає взаємодію основних акторів (Гість, Користувач, Волонтер, Адміністратор, Адміністратор системи) з функціоналом веб-застосунку.
* UML діаграма компонентів (Component Diagram): Ілюструє внутрішню будову застосунку. Показує розбиття на UI-шар, Context-шар, Router, а також взаємодію клієнта з бекенд-сервером та базою даних PostgreSQL.
* UML діаграма взаємодії (Interaction Overview Diagram): Фокусується на потоці керування під час процесу авторизації, створення заявки на усиновлення та її обробки адміністратором.
* UML діаграма діяльності (Activity Diagram): Деталізує алгоритм виконання бізнес-процесу "Створення та виконання волонтерського завдання", від моменту призначення до перерахунку індексу активності волонтера.
     Для підготовки технічної документації, написання коду та аналізу архітектури веб-застосунку притулку було використано сервіси штучного інтелекту. 
     Назва інструменту та версія: Gemini (Google). 
     Мета використання: Написання та оптимізація коду на React.js і Node.js, налаштування глобальної системи інтернаціоналізації, розробка складних SQL-транзакцій для імпорту/експорту реляційної бази даних, а також генерація синтаксису для UML-діаграм. 
     Внесок автора: Автор самостійно розробив архітектурну концепцію, формував технічні завдання для генерації коду, проводив інтеграцію згенерованих фрагментів (UI-компоненти, Protected Routes, API ендпоінти) у єдину систему. Також автор налаштував взаємодію з БД, провів рефакторинг згенерованого коду для уникнення помилок, тестував інтернаціоналізацію (формати дат, сортування) та перевірив логіку згенерованих UML-діаграм, забезпечивши науково-технічний стиль викладу матеріалу.
