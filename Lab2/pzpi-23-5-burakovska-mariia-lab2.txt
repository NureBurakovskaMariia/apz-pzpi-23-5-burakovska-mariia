2 ЗАВДАННЯ

     На цій лабораторній роботі потрібно розробити мобільний програмний застосунок для будь-якої поширеної на сьогодні мобільної платформи. Мобільний застосунок повинен бути частиною системи і повинен взаємодіяти з нею. Для реалізації програмного застосунку можна використовувати технології для реалізації програмного забезпечення для мобільних платформ, вказані лектором, а саме Kotlin для Android та Swift для iOS.

     3 ОПИС ВИКОНАНОЇ РОБОТИ

     Система являє собою єдиний цифровий простір для управління притулками для тварин. У ході виконання лабораторної роботи було спроєктовано архітектуру мобільного клієнта (Android), розробленого мовою Kotlin з використанням декларативного UI-фреймворку Jetpack Compose.
     Опис прийнятих інженерних рішень:
* архітектурний патерн (MVVM): Мобільний застосунок побудовано за патерном Model-View-ViewModel. Це дозволяє чітко розділити UI-шар (екрани Jetpack Compose) від бізнес-логіки (ViewModels) та шару даних (Repositories);
* мережева взаємодія: Для зв'язку з бекендом (Node.js) використовується клієнт Ktor (HTTP/JSON). Взаємодія відбувається через REST API. Дані передаються у вигляді DTO (Data Transfer Objects), що забезпечує чіткий контракт між клієнтом та сервером;
* локальне збереження даних: Для збереження сесійних даних користувача (токен, ідентифікатор, пошта) імплементовано Preferences DataStore. Це дозволяє зберігати стан авторизації навіть після перезапуску застосунку;
* оптимістичне оновлення інтерфейсу (Optimistic UI): Для волонтерських завдань застосовано підхід оптимістичного оновлення. При зміні статусу завдання (натискання на чекбокс), стан UI оновлюється миттєво, а мережевий запит на сервер виконується у фоновому режимі. У разі помилки стан автоматично відкочується.
     Мобільний застосунок виступає клієнтом, який агрегує дані. Шар UI генерує події (Actions), які обробляються у ViewModel. ViewModel викликає методи відповідних репозиторіїв (AuthRepository, TaskRepository, DonationRepository), які через Ktor формують HTTP-запити до Node.js сервера. Сервер взаємодіє з PostgreSQL базою даних через Knex.js та повертає результат, який оновлює State у мобільному додатку.
     Для наочного представлення структури, поведінки та архітектури розробленого мобільного клієнта було побудовано ряд графічних моделей (візуалізація наведена у Додатку Б):
* UML діаграма прецедентів (Use Case Diagram): Відображає взаємодію основних акторів (звичайного Користувача та Волонтера, який успадковує базові права) з функціоналом мобільного застосунку. Визначено ключові прецеденти: авторизація, перегляд каталогу тварин, здійснення донатів, подача заявок на усиновлення та управління статусами волонтерських завдань;
* UML діаграма компонентів (Component Diagram): Ілюструє внутрішню будову Android-застосунку за патерном MVVM. На діаграмі показано розбиття на шари: UI (екрани Jetpack Compose), Presentation (ViewModels), Data (Repositories та DataStore) та Network (Ktor), а також продемонстровано напрямки потоків даних між ними та бекенд-сервером.
* ER-модель даних (Entity–Relationship Model): Описує логічну структуру даних мобільної платформи. Визначено ключові сутності (Users, Volunteers, Animals, Tasks, Donations), їхні атрибути (DTO-моделі) та типи зв'язків між ними (один-до-багатьох, один-до-одного), необхідні для коректної обробки інформації на клієнті.
* UML діаграма діяльності (Activity Diagram): Деталізує алгоритм виконання бізнес-процесу «Здійснення донату». Діаграма розбита на зони відповідальності, що дозволяє відстежити шлях від дій користувача (введення суми) через обробку логіки у ViewModel (валідація, показ індикаторів завантаження) до мережевого запиту на сервер та фінального оновлення UI (показ діалогового вікна подяки).
     Для підготовки технічної документації, написання коду та аналізу архітектури мобільного застосунку притулку було використано сервіси штучного інтелекту. 
     Назва інструменту та версія: Gemini 3.1 Pro. 
     Мета використання: Написання та оптимізація коду на Kotlin (Jetpack Compose) і Node.js, структурування технічного звіту за вимогами дисципліни, генерація синтаксису для UML та ER-діаграм у форматі Mermaid, а також проєктування складних технічних рішень. 
     Внесок автора: Автор самостійно розробив архітектурну концепцію, формував технічні завдання для генерації коду, проводив інтеграцію згенерованих фрагментів (UI-компоненти, репозиторії, маршрути бекенду) у єдину систему, тестував функціонал через Postman та верифікував код на відповідність патерну MVVM. Також автор перевірив логіку згенерованих діаграм та адаптував їх під фактичну структуру бази даних і мобільного застосунку, забезпечивши науково-технічний стиль викладу матеріалу.

15 class AnimalRepositoryImpl(
16     private val httpClient: HttpClient
17 ) : AnimalRepository {
18 
19     override suspend fun getAnimals(): Result<List<AnimalDto>, DataError> = withContext(Dispatchers.IO) {
20         safeCall<List<AnimalDto>> {
21             httpClient.get("animals")
22         }
23     }
24 
25     override suspend fun getAnimalById(id: Int): Result<AnimalDto, DataError> {
26         return try {
27             val response = httpClient.get("/api/animals/$id")
28 
29             when (response.status) {
30                 HttpStatusCode.OK -> {
31                     val animal = response.body<AnimalDto>()
32                     Result.Success(animal)
33                 }
34                 HttpStatusCode.NotFound -> {
35                     Result.Error(DataError.ApiError("Тварину не знайдено"))
36                 }
37                 else -> {
38                     Result.Error(DataError.Remote.SERVER)
39                 }
40             }
41         } catch (e: SerializationException) {
42             e.printStackTrace()
43             Result.Error(DataError.Remote.SERIALIZATION)
44         } catch (e: Exception) {
45             e.printStackTrace()
46             Result.Error(DataError.Remote.NO_INTERNET)
47         }
48     }

18 @HiltViewModel
19 class ListViewModel @Inject constructor(
20     private val animalRepository: AnimalRepository
21 ) : ViewModel() {
22 
23     private val _state = MutableStateFlow(AnimalList.State())
24     val state = _state.asStateFlow()
25 
26     private val _event = MutableSharedFlow<AnimalList.Event>()
27     val event = _event.asSharedFlow()
28 
29     init {
30         loadAnimals()
31     }
32 
33     fun onAction(action: AnimalList.Action) = viewModelScope.launch {
34         when (action) {
35             is AnimalList.Action.OnAnimalClick -> {
36                  _event.emit(AnimalList.Event.OnNavigate(route = Screen.Animals.Details(action.animalId)))
37             }
38             AnimalList.Action.OnRefresh -> loadAnimals()
39         }
40     }
41 
42     private fun loadAnimals() {
43         viewModelScope.launch {
44             _state.update { it.copy(isLoading = true) }
45             animalRepository.getAnimals()
46                 .onSuccess { list ->
47                     _state.update { it.copy(animals = list, isLoading = false) }
48                 }
49                 .onError {
50                     _state.update { it.copy(isLoading = false, error = "Failed to load") }
51                 }
52         }
53     }
54 }
